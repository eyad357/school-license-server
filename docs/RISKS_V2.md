# تقرير المخاطر — ما أُثبت وما لم يُختبر

## أُثبت بالتشغيل الفعلي (قاعدة PostgreSQL محلية مؤقتة + كود Windows الفعلي بمحاكاة Electron)
- عقد API لم يتغير؛ العميل الأصلي المبيع يعمل مع السيرفر الجديد (يشمل مع تفعيل التوقيع) — `compat-tests` (النسخة الأصلية: كل اختبارات العقد والخادم ناجحة؛ الإخفاقات السبعة الباقية فيها هي عيوب العميل نفسه التي صُحّحت).
- الترحيل 004 ثم 005 على قاعدة بشكل الإنتاج: بصمة licenses/devices/activations/products مطابقة، التفعيل القائم يعمل بعده، الترحيل متكرر الأمان، والتخطيط الجاف يتراجع.
- الكود الجديد يعمل على مخطط قبل 005 (إنشاء ترخيص/تفعيل) والكود القديم يعمل بعد 005.
- منع مفتاح برنامج A في B (تفعيل/تحقق/إلغاء)، وسياسة التعطيل، وإلزامية اختيار البرنامج (API وواجهة)، وثبات `productId` (API وSQL).
- أرقام العملاء فريدة بلا فجوات عبر البرامج؛ الدفعات بالجملة والـidempotency كما كانت (اختبارات القاعدة الأصلية كلها ناجحة بعد تعديل واحد: تحديد البرنامج صراحة).
- توقيع Ed25519: يتحقق، ويرفض التلاعب والجهاز/المفتاح الآخر؛ التوقيع معطّل بلا مفتاح؛ مفتاح تالف لا يكسر التفعيل.
- استرجاع التفعيل بعد إعادة التثبيت بلا مفتاح/بلا إنترنت، انتهاء المؤقت محليًا، منع الرجوع بالساعة، بقاء الدائم عاملًا حتى بساعة +20 سنة.

## لم يُختبر (لا أدّعيه)
1. **مثبّت Windows `.exe`**: لم يُبنَ هنا (لا Wine لتوليد الـuninstaller). كود NSIS الجديد (حماية مجلد الشواهد أثناء الترقية) جُمّع بنجاح كوحدة منفصلة فقط ولم يُشغَّل.
2. **الترقية الفعلية فوق نسخة مفعّلة مثبّتة على Windows**، وإلغاء التثبيت الحقيقي، وDPAPI/safeStorage الحقيقي (حوكيت بنموذج Local State).
3. **الإنتاج الفعلي**: لم يُلمس. بيانات الإنتاج الحقيقية غير متاحة لي؛ سلوك الترحيل على بياناتها مبني على قاعدة بنفس الشكل لا عليها.
4. أداء/تحمّل Railway، وأي انقطاع أثناء التبديل.
5. `verify:viewer` وما بعده في المشروع Windows ينقصه ملفات عينة من جهاز المطوّر؛ و`license-periodic` فيه فشل قديم (افتراض OFFLINE_GRACE قديم) موجود في النسخة الأصلية.

## مخاطر متبقية
| الخطر | الأثر | التخفيف |
|---|---|---|
| قاعدة بيانات خاطئة/فارغة خلف السيرفر | قفل كل العملاء (`invalid`) | O13؛ لا تغيّر `DATABASE_URL`؛ تحقق من الأعداد |
| `deleteAppDataOnUninstall: true` | إلغاء التثبيت يمسح بيانات المدرسة (store.json) | قرار المالك؛ لم يُغيَّر |
| نسخ `device-id.json` + ملف الترخيص لجهاز آخر | استخدام جهاز إضافي دون علم السيرفر حتى أول اتصال | ضعف قائم؛ التحقق بعد الاتصال يحدّد عدد الأجهزة المعروفة |
| تقديم ساعة الجهاز للأمام (مؤقت موقّع) | انتهاء مبكر حتى الاتصال | يُصحّح بالاتصال/إعادة التفعيل |
| ضياع المفتاح الخاص للتوقيع | لا توقيع جديد (القديم يبقى صالحًا ما دام المفتاح العام في التطبيق) | احتفظ بنسخة آمنة؛ دوّر المفاتيح عبر `kid` |
| HTTP 400 على النجاح | عملاء جدد يعتمدون على الكود قد يخطئون | موثّق في `API_CONTRACT.md`؛ العميل الحالي يتجاهله |
| عملاء نسخة V3 (userData باسم عربي) | تفعيلهم يُلتقط لكن بيانات المدرسة في مجلد آخر لم تُنقل | اسأل: هل بيع أحد على V3؟ |
| بقاء الأعمدة/الحارس بعد رجوع الكود | لا ضرر | موثّق |
