# استيراد البيانات القديمة إلى مخطط v4.1

السكربت: `scripts/import-legacy-data.js` — **إضافة فقط**: لا يحذف ولا يعدّل ولا يستبدل أي سجل.

## ما الذي يفعله
- يقرأ ملف SQL نصي (data-only) من القاعدة القديمة (للقراءة فقط).
- يتحقق من سلامة الملف (المخطط القديم، العلاقات، تكرار المفاتيح) ومن أن الهدف بمخطط v4.1.
- يرقّم العملاء القدامى 1..N حسب (created_at, id) ويحدّث `customer_number_counter`.
- `sale_status='sold'` لمن له اسم (نفس قاعدة الترحيل 007)، وإلا `unsold`. لا يخترع سعرًا ولا حالة دفع.
- أي تعارض (نفس المعرّف بمحتوى مختلف، مفتاح ترخيص/جهاز/مرجع دفع مستخدم في سجل آخر، علاقة ناقصة) يوقف كل شيء مع تراجع كامل.
- يقارن كل صف قديم بما دخل فعليًا قبل الـ COMMIT، ويسجّل سطرًا في `admin_audit_log`.
- إعادة التشغيل آمنة: الصفوف الموجودة بمحتوى مطابق تُتخطّى.

## الاستخدام
```powershell
$env:DATABASE_URL = "<رابط القاعدة الهدف>"      # لا تكتبه في أي ملف
node scripts/import-legacy-data.js --source C:\DB-Backup-Test\old-data.sql --plan    # تجربة: تتراجع دائمًا
node scripts/import-legacy-data.js --source C:\DB-Backup-Test\old-data.sql --apply   # التنفيذ
Remove-Item Env:DATABASE_URL
```
- الهدف يجب أن يكون **فارغًا** من العملاء/التراخيص (وإلا يرفض) كي تبقى الأرقام 1..N؛ `--allow-non-empty` يضيف بعد الموجود.
- المطلوب قبله: ترحيلات 004–007 مطبّقة على الهدف (`docs/LOCAL_RUN.md`).
- **لا تشغّله على قاعدة الإنتاج** قبل نسخة احتياطية ومراجعة تقرير `--plan` وموافقة صريحة.
