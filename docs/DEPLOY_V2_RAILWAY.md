# دليل نشر الإصدار الجديد (منصة متعددة البرامج) على Railway — خطوة بخطوة

> لم يُنفَّذ أي أمر من هذا الدليل على الإنتاج. كل ما جُرّب كان على قاعدة PostgreSQL محلية مؤقتة.
> ترتيب الأمان: **نسخة احتياطية ← تحقق من استعادتها ← تجربة الترحيل ← ترحيل الإنتاج (الكود القديم ما زال يعمل) ← نشر الكود ← تحقق ← رجوع إن لزم.**
> إن كان الإنتاج لم يُرحَّل بعد إلى 004 (إدارة العملاء)، اتبع أولًا `RAILWAY_DEPLOY.md` الموجود (004) ثم هذا الدليل (005). الترحيلان إضافيان ومستقلان ومعاملة واحدة لكل منهما.

## 0) شروط مسبقة
- لا تفتح أي أمر على الإنتاج قبل نجاح الخطوات 1–4.
- لا تضع `.env` أو الأسرار أو ملفات `.pem` في Git أو ZIP.
- اختر وقتًا هادئًا. «صفر انقطاع» غير مضمون: Railway يبدّل الحاوية وقد يفشل عدد قليل من الطلبات؛ عميل Windows لا يعتبر فشل الشبكة إلغاءً (اختُبر: O1–O12).

## 1) نسخة قابلة للرجوع من الكود
```
git status                       # نظيف
git tag pre-multiproduct && git push origin pre-multiproduct
```
في Railway اترك النشر الحالي في قائمة Deployments (يمكن إعادة نشره). دوّن Start Command الحالي (`node src/index.js`).

## 2) نسخة احتياطية من القاعدة + التحقق من استعادتها (إلزامي)
```
pg_dump "$PROD_URL" --format=custom --no-owner --no-privileges -f prod-before-005.dump
createdb restore_check && pg_restore --no-owner -d restore_check prod-before-005.dump
```
قارن الأعداد (نفس الاستعلام على الإنتاج وعلى النسخة المستعادة) ودوّنها:
```sql
select (select count(*) from licenses) licenses, (select count(*) from devices) devices,
       (select count(*) from activations) activations, (select count(*) from activations where deactivated_at is null) active_slots,
       (select count(*) from customers) customers, (select count(*) from products) products;
select product_id, count(*) from licenses group by 1;     -- يجب أن يظهر school-accreditation
```

## 3) تجربة كاملة على نسخة (ليس الإنتاج)
1. أنشئ خدمة/قاعدة اختبار من `prod-before-005.dump` (أو قاعدة محلية `restore_check`).
2. التخطيط الجاف (لا يغيّر شيئًا — يتراجع دائمًا):
```
DATABASE_URL="<رابط النسخة>" npm run migrate:plan:005
```
مثال على المخرجات في `plan-005-sample-output.txt`: «ROLLED BACK. Nothing was saved» وبصمة (md5) الجداول المحمية متطابقة قبل/بعد.
3. طبّق على النسخة: `DATABASE_URL="<رابط النسخة>" npm run migrate:apply:005` ثم أعد الاستعلام في الخطوة 2 وقارن: **يجب أن تتطابق كل الأعداد**.
4. شغّل نسخة السيرفر الجديدة على النسخة وجرّب: تسجيل الدخول للوحة، تبويب البرامج، إنشاء ترخيص تجريبي، تفعيل/تحقق من جهاز تجريبي. **لا تستخدم مفاتيح عملاء حقيقيين.**

## 4) ترحيل الإنتاج (الكود القديم ما زال يعمل بعده)
```
DATABASE_URL="<رابط الإنتاج>" npm run migrate:plan:005     # للمراجعة: يتراجع دائمًا
DATABASE_URL="<رابط الإنتاج>" npm run migrate:apply:005
```
المُشغّل يرفض الإكمال ويتراجع إن تغيّر أي صف في licenses/devices/activations/products. أعد استعلام الأعداد وقارنها بالخطوة 2. الكود القديم لا يستخدم الأعمدة الجديدة فيعمل كما هو (اختُبر).

## 5) نشر الكود الجديد
ادفع الفرع ← Railway ينشر. لا متغيرات بيئة جديدة إجبارية. **لا تضبط `LICENSE_SIGNING_PRIVATE_KEY` الآن** (انظر `HYBRID_LICENSING.md`: يُضبط بعد توزيع إصدار Windows الجديد).

## 6) التحقق بعد النشر
- `GET /health` ← ok.
- لوحة الإدارة: تبويب «البرامج» يعرض `school-accreditation` وأعداده تطابق الخطوة 2.
- تحقق بجهاز **تجريبي** فقط: ترخيص تجريبي جديد ← تفعيل ← تحقق ← إلغاء.
- أعداد التراخيص/الأجهزة/الخانات النشطة مطابقة للخطوة 2 (+ أي نشاط فعلي في الدقائق الأخيرة).
- إن كان لديك جهاز Windows مفعّل لاختبارك الشخصي: افتح البرنامج؛ يجب أن يبقى مفعّلًا.

## 7) خطة الرجوع
| المشكلة | الإجراء |
|---|---|
| خلل في الكود بعد النشر | Railway ← Deployments ← النشر السابق ← Redeploy (أو `git revert`). **لا تلمس القاعدة**: الأعمدة الجديدة لا تضر الكود القديم. |
| فشل الترحيل | لا شيء: معاملة واحدة تتراجع تلقائيًا. أصلح السبب وأعد `migrate:plan:005`. |
| فقدان/تلف بيانات (نادر) | **لا تكتب فوق الإنتاج.** أنشئ قاعدة جديدة من `prod-before-005.dump`، تحقق من الأعداد، غيّر `DATABASE_URL`، أعد النشر، وأبقِ القديمة للفحص. ما حدث بعد النسخة (تفعيلات جديدة) لن يكون فيها فخذ نسخة جديدة قبل أي إجراء. |
| تعطيل برنامج بالخطأ | لوحة البرامج ← «تفعيل». لا يتأثر أي جهاز مفعّل أثناء التعطيل. |
| تراجع عن 005 نهائيًا (غير موصى) | غير لازم تقنيًا. إن أردت: على نسخة أولًا `ALTER TABLE products DROP COLUMN description, DROP COLUMN status, DROP COLUMN updated_at; DROP TRIGGER trg_products_guard_product_id ON products; DROP FUNCTION products_guard_product_id();` (يحذف وصف/حالة البرامج فقط). |

## 8) تحذير مهم (أُثبت بالاختبار: O13)
إن أشار الخادم إلى قاعدة بيانات **مختلفة أو فارغة** فسيرد `invalid` لكل جهاز ويقفل عميل Windows. لا تغيّر `DATABASE_URL` ولا تستعد قاعدة بديلة إلا بعد التحقق من أعدادها.
